# 真实查询质量修复与 Pi 回放（2026-09-26）

## 起点

10 条 Tavily 配对查询的离线检查暴露两类 Search API 问题：

1. Agent 生成的短语式“手机配件 / 便携储能 + 地区 + 市场”查询不以“研究 / 分析”开头，因此绕过已有行业实体约束与英文检索变体。实际前列混入年份百科页、无关手机横评和成人内容页。
2. SearXNG 经常把 `Sep 7, 2026 ·` 这样的日期写在摘要开头，却不给结构化日期；其 `time_range` 也没有严格清除已知过期结果。

本轮让已知行业词的短语式查询也启用实体约束及英文变体；有明确时间窗口时，英文变体不再额外塞入当前年份。日期只从摘要**开头的明确格式**提取，并标记为 `published_date_source=search_snippet`，不参与新鲜度加分。带 `days` / `time_range` 的请求会过滤已知日期落在窗口外的候选；无日期候选仍保留。

## Pi 同一批 63 条真实调用回放

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| HTTP 200 | 63/63 | 63/63 |
| 空结果 | 1/63 | 1/63 |
| 平均候选数（上限 20） | 18.54 | 16.63 |
| 显式 `site:` 查询越域 URL | 0 | 0 |
| 6 条已知中文行业查询的 Top 5 行业词命中 | 11/30 | 27/30 |
| 31 条带窗口新闻查询的 Top 5 有日期 | 62/154 | 133/153 |
| 上述有日期结果落在窗口外 | 3 | 0 |

修复后 133 条有日期结果中，66 条来自搜索引擎结构化字段，67 条仅来自搜索摘要；另有 20 条没有日期。这里的“行业词命中”只是自动词面检查，**不是人工相关性或可引用性标注**。前后两次搜索引擎结果会自然波动，不能把所有排序变化都归因于本轮代码。

表中修复前仅有 62 条结果带结构化日期，因此只能识别出 3 条越窗。先提取摘要日期、尚未加本地窗口过滤的中间回放识别出 22 条 Top 5 越窗结果；加过滤后的最终回放为 0。各阶段候选池并不完全相同，不能把这三个数字当作严格配对的单一效果量。

修复后的一条中文美国手机配件查询，前 5 已不再包含先前的无关成人站点，但前列仍以 2034/2035 年期的市场预测页为主；它们的摘要日期可以是最近 30 天，页面内容却未必提供近期美国市场事实。这说明“有日期、在窗口内”仍不够，下一步要核查原文、信息类型及地区证据。便携储能查询的年份百科页已退出前列，但前列同样偏向付费市场预测报告。

本次只重放 Pi Search API，**没有新增 Tavily 调用**。逐条原始查询与新旧响应保存在本地及 Pi 的 `benchmarks/private/`，未进入部署同步。本地测试 34 passed；Pi `/ready` 的 SearXNG 与 Redis 均可用。

## 后续方向

优先对这 10 条配对样本的双方 Top 20 做人工分级，区分：原始/官方来源、近期事实、地区与型号匹配、原文可引用性，以及候选未召回还是排序靠后。当前失败切片优先指向**近期事实检索规划和来源类型识别**；只有证明可用候选已在池中却持续排位靠后，才适合做语义重排实验。
