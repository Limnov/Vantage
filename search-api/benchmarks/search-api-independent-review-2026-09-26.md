# Vantage Search API 独立质量审查（2026-09-26）

## 结论

Search API 已能在 Pi 上快速返回真实 Vantage 查询的候选网页，适合作为**有人核查的检索工具或受控灰度候选**；目前不适合作为自动研究报告的唯一证据入口。最明显的短板是查询约束冲突、地区与来源类型判断，以及对原始来源的优先级，而不是单纯缺少语义重排。

本报告只评价 Search API，不使用其他搜索服务的结果或分数。本轮未发起新的 Search API 请求；对既有 63 条 Pi 回放中的 10 条固定样本进行人工审查，并抽查若干网页原文。原始查询、请求与响应仍保存在本地 `benchmarks/private/search-api-after-window-63-2026-09-26.jsonl`，不公开或同步到 Pi。

## 方法与判定口径

- 服务层：读取既有 63 条真实 Vantage `search_market` 回放，检查状态码、空结果、冷缓存延迟。
- 搜索层：逐条看固定 10 条样本的 Top 5，检查主题、型号、地区、时间和来源类型。
- 证据层：对已找到的部分原始网页进行独立抽查。网页抽查并不等于逐页审计这 10 条样本的全部 140 条候选，也不证明 Search API 的摘要可直接作为引文。
- “可用”表示 Top 5 中有能支持主要检索意图的明确候选；“部分可用”表示有相关候选，但关键约束或来源可靠性尚不能满足；“不满足”表示 Top 5 缺乏符合核心约束的候选或返回空结果。这个分级是针对这 10 个有意涵盖难例的样本，不可外推为总体成功率。

## 服务层观察

最终冷缓存回放为 63/63 HTTP 200、1/63 空结果、平均 16.63 条候选（上限 20）；墙钟延迟 P50 1.346 秒、P95 2.275 秒。5 条显式 `site:` 查询没有越域 URL。31 条带时间窗口的新闻查询 Top 5 合计 153 条结果，133 条有日期且都在窗口内；其中 67 条日期仅来自搜索摘要，另有 20 条没有日期。日期在窗口内只能说明日期字段合规，不能说明页面包含窗口内发生的事实。

## 优先改进方向

1. **先处理查询条件冲突。** 当明确年月、`days` 和回放/当前日期互相排斥时，返回可解释的冲突信息，或生成带明示放宽条件的补充检索；不能把空结果当作“没有这个事件”。
2. **按意图区分来源类型。** 价格/规格优先官方产品与零售商，召回优先监管机构，上市优先品牌公告，市场趋势区分近期事实、历史统计与长期预测。仅靠摘要日期不能替代事实发生日期。
3. **做证据检查。** 在输出可用于报告的候选前，核查原文是否包含对应的型号、地区、时间和被引用的数值；对内部矛盾和只有营销摘要的来源降级。
4. **最后再评估语义重排。** 当前失败样本多是约束解释和候选来源类型问题。只有确认合格原文已被召回但持续排在后面，语义重排才有清晰的收益目标。

下一道产品验收应在 Vantage 的实际采集与报告链路完成：接入新 API 的灰度路径，保留回退，检查最终报告每条关键结论是否能由原文支撑。本次审查没有完成该端到端验证，也没有做长期负载或故障恢复验证。
