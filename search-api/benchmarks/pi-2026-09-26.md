## 8 条样例冷缓存测试

运行方式：清空此 Search API 专用 Redis DB，然后在 Pi 的 API 容器中运行 `scripts/benchmark.py`；8 次请求的 `cached` 均为 `false`。完整逐条数据见 [pi-2026-09-26.json](pi-2026-09-26.json)。

| 指标 | 最初 Pi 配置 | 优化后冷缓存 |
| --- | ---: | ---: |

| 数字型号错配 | 2/8 | 0/8 |

最初配置使用 Google、Bing、DuckDuckGo；Pi 上 Google 和 DuckDuckGo 遇到 CAPTCHA，Bing 对部分查询给出明显无关的页面。改为 Yahoo、Yandex 后，降低并发与任务预算，避免 advanced 模式重复发起聚合与单引擎请求，并加强数字约束、来源类型降权与中文研究指令提取。

上述“命中”仅检查一条 Top 5 结果的标题或摘要是否包含预设词。它**不能**证明页面内容可靠、时间新鲜、适合引用，也不能与 Tavily 的质量直接比较。比如冷缓存结果中，`Apple Vision Pro latest news` 的第一条是无关的聚合主题页，`Temu US seller policy 2026` 的前三条也缺少明确的官方政策来源。

## Vantage 真实指令抽查

从 Pi 上 Vantage 的现有报告记录中抽取研究指令进行搜索抽查：

- “研究最近 30 天手机配件在美国市场的机会和风险。”返回结果，但前列混入泛市场预测和无关 PDF。
- “研究最近 30 天北美便携储能市场的机会和风险，核验关键来源。”返回结果，但前列混入文档销售站点与 CSDN 文章。

现有记录只有 8 个不同的报告查询，达不到至少 50 条真实查询的质量评测规模。本轮未进行 Tavily A/B，也没有语义重排器。因此当前结论是 **Pi 部署与基础搜索可用，真实研究质量尚不足以作为 Vantage 主搜索源**。下一步应补充人工标注的真实查询、正文提取成功率和 Tavily 对照，先区分召回与排序问题，再决定语义重排的投入。

## 后续优化与复测

为解决长研究指令夹杂无关页面的问题，已将“手机配件在美国市场的机会和风险”规划为“手机配件 美国 市场”等有界查询，并为当前常见产品补充英文市场与合规查询。市场研究结果必须涉及目标产品；标题不涉及产品、摘要未涉及目标地区的结果降权。文档售卖站点和泛内容页面也会降权。普通短查询保持原有检索路径。

最新 Pi 冷缓存 8 条样例测试见 [pi-2026-09-26-v3.json](pi-2026-09-26-v3.json)：样例词 Top 5 命中 8/8，数字型号错配 0/8，空结果 0/8，P50 1.354 秒，P95 1.803 秒。本地单元与 API 测试 20/20 通过。两个真实长指令在 Pi 上都返回 8 条结果；手机配件查询的无关金融 PDF、英国站点，以及储能查询的文档售卖页和 CSDN 页面，不再进入前列。一次通过 HTTP API 的手机配件请求返回 200、5 条结果，未命中缓存，搜索响应时间 2.43 秒。

剩余质量问题仍明显：手机配件查询前列多为泛市场报告，储能查询前列仍有营销内容和泛市场预测。部分结果仅在搜索摘要前缀提供日期，API 的 `published_date` 仍为空，不能据此自动核实“最近 30 天”的事实。8 条样例的词面命中不衡量真实性或可引用性，仍需更多人工标注的 Vantage 真实查询和 Tavily A/B。当前不建议切换 Vantage 主搜索源。
